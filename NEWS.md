## RUMBLE 3.2.0

### Major Methodological Corrections & New Features
* **Class Imbalance Handling Flexibility:** Introduced `class_balance_method` to `RUMBLE()`, allowing users to choose between `"downsample"` (default), `"class_weights"` (native per-class weighting at the engine level -- `ranger::class.weights` for RF and `xgboost::scale_pos_weight` for XGB -- preserving all training data; ENET and KNN have no native per-class weighting mechanism and are fit unweighted under this mode), or `"none"`. This ensures robust performance on imbalanced datasets without unnecessarily discarding data, especially for small cohorts.
* **Feature Stability Filtering:** Added `apply_stability_filter` to `RUMBLE()`. When enabled, only features appearing in the top-N for at least `min_fold_frequency` fraction of folds are included in the final integrated biomarker table and consensus plots. The raw `feature_frequency` table remains unfiltered for comprehensive auditing.
* **CLR / Prevalence-Filter Ordering Fix:** Corrected the intra-fold preprocessing order. CLR transformation is now applied strictly *after* the intra-fold prevalence filter, so the per-sample CLR geometric mean is computed only over taxa that survive filtering. Previously, CLR was computed before filtering, so taxa later discarded still contributed to the log-ratio denominator -- a substantive computational inconsistency with the documented anti-leakage design, not merely a documentation gap. All downstream CLR-transformed values (train and test, per outer fold) are affected; the `.apply_clr()` pseudocount default is unchanged (`1e-6`) but is now user-configurable (see `pseudocount` below).
* **Weighted Direction Metric in Global Consensus:** The `SHAP_Rho` direction metric in the weighted global consensus (`global_importance_test`/`global_importance_train`) is now aggregated using the same MCC-derived per-model weight already applied to the magnitude metric (`mean_abs_contribution`). Previously, magnitude was weighted by model performance but direction was not, an inconsistency within the same consensus step.
* **Removed Unused Consensus Path:** Removed the `model_weights` parameter and the associated `global_importance` field from `computeFeatureImportance()`, along with the per-fold performance-weight calculation in `run_analysis.R` that fed it. Neither was consumed downstream -- the actual reported consensus has always been computed independently from raw per-fold SHAP values. The only remaining performance-weighting mechanism is the MCC-based `global_weights` used in the global consensus step, matching the manuscript's Eq. 5.
* **Documentation Debt -- `shap_data` Removal:** Backfilling documentation for an earlier, previously undocumented change: the `shap_data` parameter (`"train"`/`"test"`/`"all"`) no longer exists. `RUMBLE()` now always computes SHAP on both training and test partitions; the test-set signature is used as the primary consensus source when available (gold standard), and the training-set signature is retained for the train/test overfitting diagnostic (`results$shap_overfitting`). Examples referencing `shap_data` in older documentation are stale and have been corrected.
* **`pseudocount` Now Configurable:** Re-exposed `pseudocount` as a top-level `RUMBLE()` parameter (default `1e-6`, matching the previous hardcoded value) and propagated it to all three internal `.apply_clr()` call sites. Previously the parameter existed only on the internal `.apply_clr()` helper and was hardcoded at every call site inside the pipeline, so it could not be changed without editing the package. This is a prerequisite for running a pseudocount sensitivity analysis without hand-editing source.
* **`min_fold_frequency` Self-Diagnostic:** When `apply_stability_filter = TRUE`, `RUMBLE()` now emits an informational message if the requested `min_fold_frequency` is not an exact multiple of `1 / (n_models_admitted * outer_folds)` -- the actual denominator used by `calculateFeatureFrequency()` -- reporting the nearest reachable threshold at or below the requested value. This generalizes to any combination of `outer_folds` and admitted models the specific case previously found for `outer_folds = 3`, where `min_fold_frequency = 0.7` was silently equivalent to unanimity rather than "70% of folds." The message is gated behind `apply_stability_filter` (default `FALSE`) so it stays silent for the common case where the stability filter is never enabled.
* **New `plotShapDependence()`:** Added a SHAP dependence plot (feature value on the x-axis, raw SHAP contribution on the y-axis, one facet per taxon), complementing `plotShapBeeswarm()` with a direct scatter view of the feature-to-SHAP relationship, useful for inspecting non-monotone or threshold patterns that a color-gradient beeswarm can only insinuate. Wired into the main `RUMBLE()` output: both the combined (all-taxa consensus) plot and the per-model plot are now included in the returned `plots` list and exported as PNG files (`<project_name>_shap_dependence.png` and `<project_name>_<model>_shap_dependence.png`) alongside the other SHAP plots.
* **Documentation/Verbosity Fixes:** Corrected the `plotOOFDensity()` roxygen description, which claimed the plot "reveals calibration issues," to correctly describe discrimination (class separability) rather than calibration -- the plot subtitle itself was already correct, only the docstring was misleading. `createExplainers()` now accepts a `verbose` argument and respects it (previously it always printed "Creating DALEX explainers..." regardless of `RUMBLE(..., verbose = FALSE)`).
* **Safer Parallelism in `computeFeatureImportance()`:** SHAP/permutation importance computation no longer falls back to single-core execution for the *entire* model set just because an XGBoost explainer is present. Explainers are now split into an XGBoost group (always run sequentially, since `xgb.Booster` holds its trained state as a C pointer -- `externalptr` -- that cannot be serialized to `future::multisession` worker processes) and a non-XGBoost group (RF/ENET/KNN, still eligible for `future::multisession` parallelism when `n_cores > 1`). Both groups feed the same downstream permutation and SHAP-exact computations; results are combined afterward. This removes unnecessary serialization for the common case of a mixed model pool, while preserving the original safeguard against the `externalptr` crash for XGBoost specifically.
* **New `RUMBLE_crossCohort()`:** Added a function to evaluate whether a biomarker signature generalizes across studies (train-on-one, test-on-other). It reuses the per-outer-fold fitted workflows saved by `RUMBLE(output_dir = ...)` to `<prefix>_trained_fold_models.rds` -- no re-tuning -- aligning a target cohort's abundance table to each fold's own taxa vocabulary (missing taxa become structural zeros; taxa unseen in training are dropped), reapplying that fold's CLR pseudocount, and predicting with `predict(model_fit, newdata, type = "prob")` (which automatically re-applies the fold's own recipe, including its training-set normalization). Per-(fold, algorithm) predictions are combined with the same MCC-based weighting used for the algorithm-level weighted consensus (Eq. 5), but computed per (fold, algorithm) unit instead of per algorithm. Returns both a per-algorithm breakdown (`$per_model`) and a pooled result across every unit (`$overall`), each with predictions, standard metrics (F1, accuracy, balanced accuracy, MCC, ROC AUC), and per-unit weights. `tax_level`, `remove_unclassified`, `unclassified_patterns`, and `pseudocount` must match the source cohort's settings exactly, since that configuration is not stored inside `fold_results`.

### Visualization Fixes
* **New internal label helper (`.shortenTaxonLabel()`):** Unclassified taxa previously fell back to their full lineage string (e.g. `Bacteria_Actinomycetota_Coriobacteriia_Coriobacteriales_Eggerthellaceae_`) as the display label, which crowded axis labels and truncated facet strip titles in several plots. Display labels are now shortened to the last 1--2 non-empty taxonomic ranks; the underlying `variable` values used for joins/matching are untouched. Applied in `plotShapGlobal()`, `plotShapBeeswarm()`, `plotShapDependence()`, `plotTaxaPrevalence()`, `plotBiomarkerIntegrated()`, and `plotSHAPvsPermutation()`.
* **`plotRocCurves()`:** Fixed facet strip titles (model name + AUC +/- SD) being clipped on both edges. The stat label now wraps onto a second line before `"(AUC = ..."` and `strip.clip = "off"` with a smaller `strip.text` prevents truncation.
* **`plotMetricsComparison()`:** Reworked to accept an optional `fold_metrics` argument; when supplied, the plot shows per-model/per-metric mean +/- SD as error bars plus individual per-fold points overlaid on each bar, instead of a single point estimate with no indication of variability. Replaced `ggplot2::ylim(0, 1)` with `ggplot2::coord_cartesian(ylim = c(lower_bound, 1))`: `ylim()` silently drops any bar falling outside the fixed range, which would have discarded negative MCC values (MCC is defined on [-1, 1]) instead of just clipping the visible area. `run_analysis.R` now passes `fold_metrics = all_metrics` at the call site.
* **`plotShapBeeswarm()`:** Fixed dense point clouds (e.g. many SHAP repetitions) collapsing into a solid mass at `ggbeeswarm::geom_beeswarm(corral = "gutter")`'s edge; switched to `corral = "random"`. An initial fix subsampled points above a per-feature cap, but this was deliberately reverted: a SHAP beeswarm should show every observation, and discarding a random subset (even of near-duplicate repetitions) distorts the plotted distribution. Point count is never reduced; instead, per-`(variable, model)` point opacity now scales down as the point count grows (`pmax(0.05, pmin(1, 300 / n()))`), so ordinary-sized plots stay fully opaque and only very dense plots (thousands of points per feature) render as a density-like gradient while still drawing every point.
* **`plotConfusionMatrices()`:** Rewritten to compute a confusion matrix per outer fold (row-normalized within each fold) and report mean +/- SD per cell, instead of a single matrix pooled from all out-of-fold predictions summed together; the pooled total is retained in parentheses for reference.
* **`plotShapDependence()`:** Reduced `strip.text` size and added `strip.clip = "off"`, matching the `plotRocCurves()` fix, to prevent facet title clipping when taxon labels are long.
* **`plotSHAPvsPermutation()`:** Capped `ggrepel::geom_text_repel()` at `max.overlaps = 15` (was `Inf`) with tuned repel parameters, and switched labels to the new shortened taxon names, to reduce label overlap on real (non-toy) data.

## RUMBLE 3.1.0

### Major Methodological Corrections & New Features
* **Nested Cross-Validation Metric Consistency:** Fixed an optimization reporting bias in the Inner CV loop. The pipeline now rigorously extracts all performance metrics (AUC, MCC, etc.) exclusively from the exact hyperparameter configuration that won the fold. Previously, metrics could be artificially inflated due to independent `max()` aggregation across different `.config` sets.
* **Generalization Gap Accuracy:** With the refactored `summarizeInnerCV()` and updated extraction in `run_analysis.R`, the reported Generalization Gap now reflects perfect mathematical alignment between the exact model tuned in the inner loop and its performance on the out-of-fold test set.

* **Minor updates and fixes** for compatibility and robustness.

## RUMBLE 2.0.0

* **Mandatory `shap_data` Parameter:** The `shap_data` parameter is now mandatory and must be explicitly specified by the user. Previously, it defaulted to `"all"`. This change enforces conscious methodological decision-making: users must now choose between `"train"` (recommended for biomarker discovery), `"test"` (for prediction-focused analysis), or `"all"` (for maximum statistical power). This ensures greater methodological rigor and transparency in analytical objectives.

## RUMBLE 1.0.0

### Major Changes & New Features
* **Integrated Differential Abundance (DA):** Added `run_da` and `da_method` parameters to the main `RUMBLE()` interface. The pipeline now validates complex machine learning predictive patterns with classical DA methods (Wilcoxon, ANCOM-BC, or ALDEx2).
* **Total Interpretability Mode:** Changed the default value of `shap_data` to `"all"` (previously `"test"`). This maximizes statistical power for SHAP calculations and ensures perfect biological alignment between SHAP importance, group prevalence, and DA Log2FC.
* **Optimized Defaults:** Adjusted default `shap_reps` to `25` (down from 100), providing an optimal out-of-the-box balance between feature ranking stability and computation time.

## RUMBLE 0.1.0

### New features
* Complete consensus machine learning pipeline for microbiome biomarker discovery (`RUMBLE()`).
* Accepts both `phyloseq` objects and count matrices as input (`prepareData()`).
* Four classification algorithms: Random Forest, XGBoost, Elastic Net, and KNN, all via `tidymodels`.
* Model-agnostic interpretability through SHAP values and permutation importance via `DALEX` (`computeFeatureImportance()`).
* Publication-ready visualizations for metrics, ROC curves, confusion matrices, SHAP summaries, integrated biomarker interpretation, and permutation importance.
* Optional removal of unclassified taxa (`remove_unclassified` parameter, default `FALSE`).
* Prevalence-based filtering and CLR transformation for compositional data.
